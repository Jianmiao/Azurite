## 已修复的清理缺陷

首次独立复查发现两个缺陷：旧释放方法忽略进程组句柄关闭失败，可能仍报告清理成功；桌面句柄交接被拒绝时，补偿关闭失败可能丢失持有记录。

新模式现使用明确检查结果的释放路径。关闭失败保留原句柄身份和错误，撤销清理成功结论，并保留隔离状态；拒绝桌面交接同时保留主要错误和清理错误，不发送确认。旧模式的释放方法没有随之改写。

新增测试调用同一份生产持有/释放逻辑，并覆盖在取得进程或线程句柄后发生失败的记录、清理和关闭。它们注入受控操作结果，没有对模拟句柄调用对应 Windows API，也没有额外写一套启动引擎代替生产逻辑。
