# efficiency-1 优化与未完成项

目标：降低静态编辑、后台和大稿修改的无效 CPU/GPU 工作，保留输入、播放及导出恢复。原始 deep-3 包不变，工作副本可独立构建和回退。

| 发现 | 当前处理 | 状态与验证边界 |
| --- | --- | --- |
| 小于 32 个面板时重复采样 | 预算取面板数与 32 的较小值 | 源码链接测试覆盖 1、8、16、31、32、640 个面板 |
| 稳定订阅反复 GetInvocationList | 比较不可变委托指针，变化时才核验并修复 | 保留多播回调、清空后修复和异常保护 |
| 按需绘制未降低 Update 频率 | 静态等待 2 秒，前台 30、后台 15 FPS | 与现有 FpsController 共用所有权；未知状态、输入、播放、导出不获取静态上限 |
| 插删时布局缓存被清空 | 同步编辑保留缓存，按行内容、样式与输出验证 | 全局 NGUI 状态匹配要求仍保留，不能声称所有行都会命中 |
| 缓存满时整表清空、死节点积累 | 有上限的逐条淘汰和同步节点删除 | 20,000 次插入/删除与增长的管理记录上限测试 |
| 动画判定扫描全部活动项，大于 256 一律活动 | 首个活动项立即返回；终止对象允许驻留，上限 4096 | 超过安全上限及空/未知项继续保护；诊断改为活动存在值 0/1 |
| Scenario 队列空不等于角色静止 | 检查角色 Spine、眨眼、Animator、位移动画和独立队列 | 可减少错误冻结；运行角色可能使静态省电不触发，这是正确保护 |
| 预览两套控制器重复查询、相机反复启停 | 共用一秒纹理快照，移除 Update 的无条件恢复 | 释放前强制实时查询；外部绑定变化保留；独立缓存生命周期检查 |
| UI 滚动连带重绘静态预览 | CacheStaticPreview 实验复用现有纹理 | 默认关闭；观察整个 PreviewScene、前面板事件及相机变化，定期重绘；不新增 RT |
| 自己的观察回调阻止屏外面板实验 | 仅识别单个本 mod 观察回调 | 外部回调和多播回调仍保守保护；保留 NativePatches 宿主门槛 |
| 原源码直接引用本机缺失的两个成员 | 一次解析可选 getter，缓存类型正确的委托 | 缺失成员按该已验证版本不存在的生产者处理；不可读/签名错误保持活动；没有扩充原生白名单 |

## 仍待完成，目标保持进行中

1. **完整对白可见行虚拟化。** 当前候选已在经核验的固定宿主上提供有界可见行池：逻辑缓存仍保持完整索引，GameObject 只覆盖视口、预读和选中行；插入、删除、重排、撤销重做、加载、保存与导出交接前恢复 dense native list。测试桩覆盖 640/5,000 行和 100 次变更，但仍不能替代 Unity 实机验收。
2. **共享 NGUI 状态重放与更多布局命中。** 该状态被其他 UILabel 共用。目前只在共享状态一致时跳过 Initialize，不能随意移除条件来追求命中率。需要匹配版本的 Initialize/DisplayChunks 原生副作用证据。
3. **原始预览 RT 硬件释放。** 小 RT 方案保留原始 RT，会同时驻留两个目标。Release 原对象的存储后，需要检查所有消费者、重建原尺寸并在导出前保证有效内容；单看屏幕 UITexture 和相机不足以证明没有其他消费者。因此没有新增释放开关，也没有宣称减掉原始 RT 显存。
4. **游戏内收益、编辑与导出回归。** 当前候选已经按 `F:\AzureArchive_100_fix` 构建并完成静态/源代码链测试，但尚未安装到正在运行的 AA；真实滚动帧时间、GPU 利用率和大稿操作延迟仍需用户验收。
