# 一次受控 capabilities 运行的输入组装

更新日期：2026-11-12。

`tools/headless/New-AzuriteFullCapabilitiesInputs.ps1` 将已固定摘要的 C 盘证据组装为供审查的输入文件。它不采集日常 AA 状态，不修改 F/E 盘或注册表，不执行准备 Apply，不启动进程试验或 AA，也不生成正向批准。

## 输入和输出

输入必须包含同一准确运行编号的已完成只读基线、单独核验的无害子进程运行证据、当前账户身份与共享状态记录、单独固定的实际预检观测，以及准确源码、辅助 DLL、编译来源的路径和摘要。入口记录上限 128 KiB；各级证据分别限定大小，检查工作目录和重解析路径，再核对摘要。

组装器核对五项共享状态根的准确路径、类型、必需标志、已选 Profile 与捕获 ActiveProfile 的一致性。执行任何四个依赖模块前先核对其准确本地路径和源码摘要。缓存顺序及环境、参数的观测必须来自单独固定的预检记录；旧缓存证据不会自动变成新的观测。原生构建结果使用一次有大小上限的读取，核对后解析同一字节数组。

输出依次为准备前事实/计划、准确权限清单、十八项源码清单、控制文件和运行意图。源码清单不反向依赖控制文件、批准或执行回执；控制文件不包含运行意图摘要，运行意图随后绑定控制文件。没有循环摘要。已有对象的组从真实基线描述符取得，新建对象的组明确指定；写入前、创建目录后及每个新文件前均检查输出祖先，全部使用不覆盖写入。

输出保持 `approvalPresent=false`、`willApply=false`、`willLaunch=false`、`runtimeAllowed=false`。模拟证据不能仅改标签就被认作真实；这也不是任意调用方的身份认证机制。真实运行仍需要单独审查的输入、正向批准及后续实际验证。
